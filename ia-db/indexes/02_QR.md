## 1. La matriz 4 × 2

El dominio es una **matriz**: cuatro librerías de escaneo × dos formas de usar la cámara. Los ocho proyectos resuelven el mismo caso de uso (leer un QR y mostrar el texto) con la misma UI, de modo que la única variable sea la librería.

| Prefijo | Librería NuGet | Motor de decodificación | Proyectos |
|---------|----------------|-------------------------|-----------|
| **BSM** | `BarcodeScanner.Mobile.Maui` 9.0.1 | ML Kit en Android **y en iOS** | `BSM.LectorQR`, `BSM.LectorQR_Dialog` |
| **BSN** | `BarcodeScanning.Native.Maui` 3.0.4 | ML Kit (Android) + **Apple Vision** (iOS) | `BSN.LectorQR`, `BSN.LectorQR_Dialog` |
| **CS** | `CameraScanner.Maui` 1.8.31 | ML Kit (Android) + **Apple VisionKit** (iOS) | `CS.LectorQR`, `CS.LectorQR_Dialog` |
| **ZN** | `CameraMaui` 1.4.5 (fork janusw de `Camera.MAUI`) | AVFoundation + decodificación **managed** ZXing | `ZN.LectorQR`, `ZN.LectorQR_Dialog` |

| Sufijo | Modo | Qué demuestra |
|--------|------|---------------|
| *(ninguno)* — «simple» | La cámara vive **en la propia `MainPage`** | El mínimo para tener un lector funcionando |
| `_Dialog` | Página lectora **aparte**, invocada y esperada | El lector como componente reutilizable que devuelve un resultado |

`ApplicationId` de todos: `com.ejemplos.devices.qr.<libreria>.<simple|dialog>` (p. ej. `com.ejemplos.devices.qr.barcodescanner_native_maui.dialog`). TFM `net10.0-android` (+ `net10.0-ios` en macOS), Android 25, iOS 15.0.

⚠️ **La carpeta de la solución miente sobre ZN.** `Ejemplos_Devices.slnx` agrupa `ZN.*` bajo la carpeta `/Ejemplos/QR/ZXing.Net.Maui/`, pero los dos `.csproj` referencian `CameraMaui` 1.4.5, no `ZXing.Net.Maui`. El estudio de NuGets trata ambas como opciones distintas (§4.2). El código usa `Camera.MAUI` + `Camera.MAUI.ZXingHelper` + `ZXing`, o sea el fork con helper de ZXing.

## 2. Por qué existe esta comparación

Fuente: `Docs/qr-nuget/README.md` §Hallazgo central y `04-recomendacion.md`.

`BarcodeScanner.Mobile.Maui` (el paquete original del proyecto) usa **ML Kit también en iOS**, y ML Kit **no publica slice de simulador `arm64`**. Eso obliga a compilar el simulador como `iossimulator-x64` bajo **Rosetta** — que Apple está retirando. El estudio (2026-06-27, read-only) evaluó 5 alternativas para volver a APIs nativas de Apple.

Ranking del estudio (`README.md` §TL;DR):

| # | Paquete | iOS nativo | Veredicto |
|---|---------|-----------|-----------|
| 🥇 | `BarcodeScanning.Native.Maui` | 🟢 Apple Vision | **Recomendado** — elimina ML Kit/Rosetta; MIT, ~856K descargas, 3.0.4 encaja con net10 |
| 🥈 | `CameraScanner.Maui` | 🟢 Apple VisionKit | Plan B equivalente (T. Galliker, MIT, net9 y net10) |
| 🥉 | `ZXing.Net.Maui` | 🟡 AVFoundation + decode managed | Máxima portabilidad de CI/simuladores (Redth/jfversluis) |
| — | `CameraMaui` (fork janusw) | 🟡 idem | Solo si además hace falta cámara genérica |
| — | Dynamsoft / Scandit / Scanbot | 🔵 motor propio | Enterprise, de pago |

**Los ocho proyectos son la ejecución de ese estudio**: el ranking se convirtió en cuatro pares comparables. La recomendación 🥇 es la que terminó en la app híbrida ([índice 08](08_App-Hibrida-Integrada.md)).

El síntoma concreto del problema está capturado en `QR/Ejemplo_Docs_QR/cicd.md`, con el log real del pipeline:

```
ld: building for 'iOS-simulator', but linking in object file
    (…/MLKitCommon.framework/MLKitCommon[arm64][2](MLKAnalyticsLogger.o)) built for 'iOS'
clang++: error: linker command failed with exit code 1
```

y la propiedad de MSBuild que el documento propone como solución:

```xml
<PropertyGroup Condition="$(TargetFramework.Contains('-ios')) AND '$(RuntimeIdentifier)' == 'iossimulator-arm64'">
    <MtouchExtraArgs>$(MtouchExtraArgs) --setenv:DYLD_LIBRARY_PATH=/usr/lib/system/introspection -gcc_flags "-Wl,-ignore_auto_link -Wl,-read_only_relocs,suppress"</MtouchExtraArgs>
    <MtouchLink>SdkOnly</MtouchLink>
    <NoWarn>$(NoWarn);MT5209;MT5212;MT5213</NoWarn>
</PropertyGroup>
```

## 3. Traducción de APIs entre las cuatro librerías

El mismo comportamiento («encender linterna», «pausar el escaneo», «cambiar de cámara») se escribe distinto en cada una. Esta tabla es el núcleo del valor comparativo del dominio.

| Concepto | BSM | BSN | CS | ZN |
|----------|-----|-----|----|----|
| Namespace | `BarcodeScanner.Mobile` | `BarcodeScanning` | `CameraScanner.Maui` | `Camera.MAUI` (+ `ZXingHelper`, `ZXing`) |
| Arranque en `MauiProgram` | — | `.UseBarcodeScanning()` | — | — |
| Control XAML | `gv:CameraView` | `gv:CameraView` | `cv:CameraView` | `gv:CameraView` |
| Evento de detección | `OnDetected` | `OnDetectionFinished` | `OnDetectionFinished` | `BarcodeDetected` (+ `CamerasLoaded`) |
| Args del evento | `OnDetectedEventArg` → `BarcodeResults` | `OnDetectionFinishedEventArg` | `OnDetectionFinishedEventArg` | `BarcodeEventArgs` → `Result` |
| Declarar formatos | `Methods.SetSupportBarcodeFormat(BarcodeFormats.QRCode \| …)` por código | `BarcodeSymbologies="QRCode,Code39"` en XAML | `BarcodeFormats="QR,Code39"` en XAML | `Camera.BarCodeOptions = new BarcodeDecodeOptions { PossibleFormats = […], TryHarder = true }` |
| Permiso de cámara | `Methods.AskForRequiredPermission()` | `Methods.AskForRequiredPermissionAsync()` | `Permissions.RequestAsync<Permissions.Camera>()` | `Permissions.RequestAsync<Permissions.Camera>()` |
| Pausar/reanudar | `Camera.IsScanning` | `Camera.CameraEnabled` | `Camera.CameraEnabled` | `Camera.BarCodeDetectionEnabled` |
| Linterna | `Camera.TorchOn` | `Camera.TorchOn` | `Camera.TorchOn` | `Camera.**TorchEnabled**` |
| Cambiar de cámara | `Camera.CameraFacing` (`CameraFacing.Back/Front`) | idem | idem | `Camera.Cameras` + `Camera.Camera` + `StartCameraAsync()` |
| Campos del resultado | `BarcodeType` / `DisplayValue` | idem (`BarcodeTypes.Unknown` → «Text») | idem | `BarcodeFormat` / `Text` |

**ZN es la de contrato más distinto:** no basta con declarar el control — hay que esperar `CamerasLoaded`, elegir explícitamente `CameraPosition.Back` y llamar a `StartCameraAsync()` (`ZN.LectorQR/Pages/MainPage.xaml.cs:22-37`).

## 4. Patrón «simple»: la cámara en la página principal

`<X>.LectorQR/Pages/MainPage.xaml.cs` (59–80 líneas). Un `CameraView` a pantalla completa, botón de linterna, botón de cambio de cámara y el handler de detección, que en las cuatro sigue la misma coreografía:

```csharp
Dispatcher.Dispatch(async () => {
    <pausar>;                                     // IsScanning / CameraEnabled / BarCodeDetectionEnabled
    await DisplayAlertAsync("QR detectado", …);
    <reanudar>;
});
```

La pausa evita que el diálogo se dispare en cascada mientras el QR sigue en cuadro. `Dispatcher.Dispatch` es necesario porque el evento de detección llega desde el hilo de la cámara.

## 5. Patrón «dialog»: la página lectora como componente

`<X>.LectorQR_Dialog/` — tres piezas:

| Pieza | Archivo | Responsabilidad |
|-------|---------|-----------------|
| Llamadora | `Pages/MainPage.xaml.cs` (40 líneas) | Instancia la página, la empuja, **awaitea** el resultado |
| Lectora | `Pages/QRLectorPage.xaml{,.cs}` (205–229 líneas) | Cámara, permiso, linterna, orientación y devolución del resultado |
| Contrato | `Models/QRContent.cs` (8 líneas) | `{ string Type; string Value; }` — desacopla el resultado del tipo de la librería |

Flujo (`BSN.LectorQR_Dialog` como referencia):

```
MainPage.OnLeerQRClicked          QRLectorPage
  new QRLectorPage()        →
  Navigation.PushAsync()    →     OnAppearing: permiso + suscribe orientación
  await ResultadoTask.Task  …     OnCameraViewOnDetecte → CompletarResultado(QRs) → PopAsync()
  ← List<QRContent>               (o OnVolverClicked → CompletarResultado(lista vacía))
```

- Canal de vuelta: `TaskCompletionSource<List<QRContent>>` público (`QRLectorPage.xaml.cs:11`), esperado en `MainPage.xaml.cs:21`.
- **Guardia contra doble completado:** `CompletarResultado` usa `Interlocked.Exchange(ref _completed, 1)` (`:128-134`), de modo que detección y botón «volver» no compitan por completar la misma tarea.
- «Cancelar» se expresa como **lista vacía**, no como `null` ni cancelación: `MainPage` lo interpreta con `FirstOrDefault()` y muestra «No se recibió ningún dato».
- Ruta registrada en `AppShell.xaml.cs` (`Routing.RegisterRoute(nameof(QRLectorPage), …)`) en las cuatro variantes, aunque la navegación real se hace con `Navigation.PushAsync/PopAsync`.
- Orientación: `UpdateLayoutOrientation` rearma el `Grid` `DynamicLayout` para portrait/landscape (`:148-205`), mismo patrón que la página de cámara del [índice 01](01_Camara.md#4-técnica-2--visor-propio-con-cameraview).

⚠️ `OnDisappearing` (`:87-104`) **no completa la tarea**: el bloque que lo haría está comentado (`:90-93`). La protección real es que tanto el camino de detección como el de «volver» llaman a `CompletarResultado`; salir con el back del sistema deja la tarea pendiente.

## 6. Observaciones

- **Readmes copiados.** `BSN.LectorQR/Readme.md`, `CS.LectorQR/Readme.md` y `ZN.LectorQR/Readme.md` son **idénticos entre sí** y los tres dicen `BarcodeScanner.Mobile.Maui` con el link al repo de JimmyPun610 — la librería de **BSM**, no la suya. Para saber qué librería usa cada proyecto hay que leer el `.csproj`, no el Readme.
- **Proyecto histórico.** El estudio de NuGets, `cicd.md` y el workflow `cd-ios-qr.Ejemplo_LectorQR_Dialog.yml` hablan de `Ejemplo_LectorQR_Dialog` (`com.ejemplos.devices.qr.dialog`), que **ya no existe en el árbol**: fue el proyecto sobre el que se hizo el prototipo y del que salieron los cuatro pares actuales. El workflow quedó ([índice 09](09_CI-CD-y-Build.md)).
- **`AdamE.Google.iOS.GoogleUtilities` 8.1.0.3** aparece solo en las variantes `_Dialog` de BSM, CS y ZN — no en las «simple» ni en ninguna de BSN. Es una dependencia del stack de Google en iOS que el paso 3 de la ruta de migración propone eliminar.
- **BSN declara `Microsoft.Maui.Controls` dos veces** en ambos `.csproj` (10.0.80 y `$(MauiVersion)`).
- `MaterialIconsOutlined-Regular.otf` es la fuente de los íconos `flash_on`/`flash_off` en las cuatro variantes `_Dialog`.
