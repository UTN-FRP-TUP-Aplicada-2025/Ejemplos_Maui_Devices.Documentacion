# 02 — Lectura QR

> **Propósito:** mapa del dominio «Lectura QR»: ocho proyectos MAUI mínimos (4 librerías × 2 formas de UI) que leen QR/Code39 con la cámara en vivo, más la documentación de evaluación de NuGets (`Docs/qr-nuget/`) y los apuntes de CI (`QR/Ejemplo_Docs_QR/`). Sirve para elegir librería, traducir la API de una a otra, entender por qué BSM complica el simulador iOS y detectar las trampas de lectura del dominio.
>
> **Fuente primaria:** `Ejemplos_Devices/QR/**` · `Ejemplos_Devices/Docs/qr-nuget/**` · `.github/workflows/cd-ios-qr.*.yml` · `Ejemplos_Devices/Ejemplos_Devices.slnx` (commit `285f6fb`).
>
> **Rutas:** relativas a la raíz del repo de código. `QR/` abrevia `Ejemplos_Devices/QR/`, y `qr-nuget/` abrevia `Ejemplos_Devices/Docs/qr-nuget/`.
>
> **Fuera de alcance:** el lector QR embebido en la app híbrida (`Integrada/Ejemplo_Maui_Hibrida/LibApp/Devices/QRLector/**`, `QrCommandHandler`) → [08_App-Hibrida-Integrada](08_App-Hibrida-Integrada.md).

### §2.1 Flujo de la variante _Dialog (idéntico en las 4 librerías)

```
MainPage.OnLeerQRClicked                        (QR/*_Dialog/Pages/MainPage.xaml.cs:12-39)
 ├─ BtnLeerQR.IsEnabled = false                  evita doble apertura
 ├─ var destinoPage = new QRLectorPage();
 ├─ await Navigation.PushAsync(destinoPage);    :19  (push directo, no Shell.GoToAsync)
 ├─ List<QRContent> qrs = await destinoPage.ResultadoTask.Task;   :21
 └─ qrs.FirstOrDefault() → LbQR.Text  |  vacío → alerta «Cancelado»
QRLectorPage
 ├─ OnAppearing: RequestCameraPermission() (resultado ignorado) + suscribe MainDisplayInfoChanged
 ├─ evento de detección → mapea a List<QRContent> → Dispatcher.Dispatch:
 │     detener cámara/detección → CompletarResultado(QRs) → PopAsync()
 ├─ OnVolverClicked → CompletarResultado(lista vacía) → PopAsync()
 └─ CompletarResultado: Interlocked.Exchange(ref _completed, 1) == 0 → TrySetResult
                                               (BSM: QRLectorPage.xaml.cs:136-142)
```

- La guarda `Interlocked` hace que solo el primer resultado (detección o «Volver») complete la tarea.
- `AppShell.xaml.cs:12` registra `Routing.RegisterRoute(nameof(QRLectorPage), …)`, pero la navegación usa `Navigation.PushAsync`: la ruta queda registrada sin uso (⚠️ §8.8).

### §4.1 Patrón común del handler de detección

```csharp
// BSN.LectorQR_Dialog/Pages/QRLectorPage.xaml.cs:46-64 (las otras tres son equivalentes)
foreach (var b in e.BarcodeResults)
    QRs.Add(new QRContent { Type = b.BarcodeType == BarcodeTypes.Unknown ? "Text" : b.BarcodeType.ToString(),
                            Value = b.DisplayValue });
this.Dispatcher.Dispatch(async () => {
    Camera.CameraEnabled = false;   // detener cámara (antes: IsScanning = false)
    CompletarResultado(QRs);
    await Navigation.PopAsync();
});
```

- El evento llega fuera del hilo de UI; por eso la UI se toca dentro de `Dispatcher.Dispatch`.
- En la variante simple, el patrón es pausar → `DisplayAlertAsync` → reanudar (p. ej. `BSN.LectorQR/Pages/MainPage.xaml.cs:52-57`).
- Los comentarios «antes: IsScanning = false» en BSN, CS y ZN marcan que se portaron desde BSM, tal como lo describe `qr-nuget/05-plan-migracion.md:174-175`.

## §6 iOS: ML Kit, simulador y recomendación

### §6.1 El problema (BSM)

| Hecho | Fuente |
|---|---|
| `BarcodeScanner.Mobile.Maui` 9.0.1 usa Google ML Kit también en iOS | `qr-nuget/README.md:13-14`, `Docs/otros/propuesta-rosetta.md:31` |
| ML Kit no publica slice de **simulador arm64** (solo `arm64` device y `x86_64` simulador): el linker falla con `ld: building for 'iOS-simulator', but linking in object file (…MLKitCommon…) built for 'iOS'` | `Docs/otros/propuesta-rosetta.md:32-34`; log en `QR/Ejemplo_Docs_QR/cicd.md:125-126,139` |
| El build de dispositivo `ios-arm64` compila bien; solo falla el simulador | `Docs/otros/propuesta-rosetta.md:17-18,42` |
| Workaround adoptado: compilar el simulador como `iossimulator-x64` y correrlo con Rosetta 2 | `propuesta-rosetta.md:45-46`; `cd-ios-qr.BSM.*.yml:44-45` (RID x64 activo) |
| Paquete extra del workaround: `AdamE.Google.iOS.GoogleUtilities` 8.1.0.3 condicionado a `iossimulator-x64` | `BSM.LectorQR_Dialog.csproj:78-80`; `qr-nuget/01-analisis-uso-actual.md:26-28` |
| Rosetta está en retirada: el workaround tiene fecha de caducidad | `qr-nuget/README.md:16-18` |
| El simulador iOS no tiene cámara real: el escaneo en vivo se valida en un iPhone físico de todos modos | `qr-nuget/03-matriz-rid.md:28`; `05-plan-migracion.md:229` |

### §6.2 Workarounds documentados (sin aplicar en los `.csproj` actuales)

| Bloque MSBuild | Para qué | Fuente |
|---|---|---|
| `NoWarn MT5209;MT5212` + `MtouchExtraArgs --ignore-native-library-conflict` | Librerías Google duplicadas (Firebase + ML Kit) | `Ejemplo_Docs_QR/Readme.md:68-74` |
| `iossimulator-arm64`: `--setenv:DYLD_LIBRARY_PATH=/usr/lib/system/introspection` + `NoWarn MT5209;MT5212;MT5213` | Forzar el build del simulador arm64 | `Readme.md:78-87,105-115` |
| ídem + `-gcc_flags "-Wl,-ignore_auto_link -Wl,-read_only_relocs,suppress"` + `MtouchLink=SdkOnly` | Bloque marcado «solucion» | `cicd.md:248-254` |
| `dotnet build -f net10.0-ios -p:RuntimeIdentifier=ios-arm64 -p:BuildIpa=true -p:EnableCodeSigning=false` | Verificar en CI compilando para dispositivo y no para simulador | `Readme.md:90-103` |

> Ninguno de los 8 `.csproj` contiene `DYLD_LIBRARY_PATH` ni `ignore-native-library-conflict` (verificado leyendo los `.csproj`): son apuntes para consulta.

### §6.3 Recomendación para iOS

| Ranking (`qr-nuget/README.md:36-42`) | Paquete | iOS | Proyecto del repo |
|---|---|---|---|
| 1 — recomendado | `BarcodeScanning.Native.Maui` 3.0.4 | Apple Vision (sin ML Kit ni Rosetta; habilita el simulador arm64) | BSN |
| 2 — plan B | `CameraScanner.Maui` 1.8.31 | Apple VisionKit | CS |
| 3 — portabilidad | `ZXing.Net.Maui` | AVFoundation + decodificación *managed* | **ningún proyecto lo usa** (⚠️ §8.1) |
| solo con cámara genérica | `CameraMaui` (fork janusw de `Camera.MAUI`) | AVFoundation + ZXing *managed* | ZN |
| actual / comparativo | `BarcodeScanner.Mobile.Maui` 9.0.1 | ML Kit | BSM |

- El criterio de `qr-nuget/04-recomendacion.md:11-14` es doble: soporte nativo en iOS y confianza del autor.
- El reflejo en la CI es que BSN, CS y ZN compilan el simulador `iossimulator-arm64`, mientras BSM usa `iossimulator-x64` + Rosetta (`cd-ios-qr.*.yml:44-45`, `:424-427`).
- La decisión está registrada en el repo hermano de documentación como ADR-0004 (`Ejemplos_Maui_Devices.Documentacion/Ejemplos_Maui_Devices-docs/docs/04-decisions/0004-qr-bsn-recomendada-ios.md`).
- En Android, según la matriz, las librerías con ML Kit (BSM, BSN, CS) no dan **x86 de 32 bits** pero sí **x86_64**; `ZXing.Net.Maui` cubre ambas y `CameraMaui` (la que usa ZN) figura ⚠️ en x86 (`qr-nuget/03-matriz-rid.md:14-18,27`). ⚠️ `05-plan-migracion.md:230` contradice la matriz: afirma que con ML Kit «el escaneo no corre en emuladores x86/x86_64» y recomienda probar en un dispositivo arm64 físico. Cuál de los dos vale para el emulador x86_64: (no verificado).
- Los ocho `.csproj` declaran igual `android-x86` en `RuntimeIdentifiers` (`:30`/`:32`), aunque ML Kit no lo soporte según la matriz.

## §8 Trampas de lectura y discrepancias ⚠️

### §8.1 ⚠️ «ZN» no usa ZXing.Net.Maui

- La carpeta de solución se llama `/Ejemplos/QR/ZXing.Net.Maui/` (`.slnx:179`) y el `ApplicationId` es `com.ejemplos.devices.qr.zxing_net_maui.*` (`ZN.LectorQR.csproj:17`).

- Ningún `.csproj` del repo referencia `ZXing.Net.Maui` (`CameraView`, no `CameraBarcodeReaderView`). Para ver la API de ZXing.Net.Maui solo está la ficha `qr-nuget/02-alternativas-nuget.md:85-120`.

### §8.3 ⚠️ `qr-nuget/` describe proyectos que cambiaron

- La evaluación habla de `Ejemplo_LectorQR_Dialog` (`qr-nuget/README.md:4`, `01-analisis-uso-actual.md:10-31`), que **ya no existe** en `QR/`. Su contenido (BSM + `QRLectorPage`) es el de `BSM.LectorQR_Dialog`.

- Los 9 `cd-ios-qr.*.yml` tienen el disparador `push` **comentado** (`:5-13`) y solo `workflow_call` (`:15`). Ningún otro workflow del repo los invoca con `uses:` (búsqueda en `.github/workflows/`), así que no corren solos. Si se invocan desde fuera del repo: (no verificado).

Detalle de la automatización → [09_CI-CD-y-Build](09_CI-CD-y-Build.md).

### §8.7 ⚠️ `AdamE.Google.iOS.GoogleUtilities` donde no hace falta, y falta donde sí

- El `ItemGroup` condicional a `iossimulator-x64` aparece en BSM, CS y ZN **_Dialog** (`:78-80`). CS (VisionKit) y ZN (ZXing *managed*) no usan ML Kit en iOS según `qr-nuget/02-alternativas-nuget.md`; además sus workflows compilan arm64, así que la condición nunca se cumple en CI. Es herencia de la plantilla.
- `BSM.LectorQR` (simple), cuyo workflow sí compila `iossimulator-x64` (`cd-ios-qr.BSM.LectorQR.yml:45`), **no** tiene ese paquete. Si eso rompe el build x64: (no verificado).

### §8.8 Ruta registrada sin uso

`Routing.RegisterRoute(nameof(QRLectorPage), …)` (`QR/*_Dialog/AppShell.xaml.cs:12`) no se usa, porque `MainPage` navega con `Navigation.PushAsync`. El `AppShell` de _Dialog oculta la barra (`Shell.NavBarIsVisible="False"`, `AppShell.xaml:8`) y las páginas también (`NavigationPage.HasNavigationBar="False"`).

### §8.9 BSM _Dialog no descarta lotes vacíos

`OnCameraViewOnDetecte` de BSM (`BSM.LectorQR_Dialog/Pages/QRLectorPage.xaml.cs:47-72`) cierra la página aunque `e.BarcodeResults` venga vacío. En ese caso `MainPage` mostraría «Cancelado». BSN sí corta con `if (QRs.Count == 0) return;` (`:55`). Si BSM puede emitir `OnDetected` sin resultados: (no verificado).

### §8.10 Permiso no bloqueante en _Dialog

- En BSM, BSN y CS _Dialog, `OnAppearing` hace `await RequestCameraPermission();` y descarta el resultado (`BSM…/QRLectorPage.xaml.cs:118`). Si el usuario lo deniega, la cámara queda en negro y no aparece aviso (`qr-nuget/01-analisis-uso-actual.md:85-86,152`).
- Hay un bloque comentado para completar la tarea en `OnDisappearing` (`:98-101`). Si la página se cierra con el «atrás» del sistema, la `ResultadoTask` no se completa y el `await` de `MainPage` queda pendiente (consecuencia inferida del código; no verificado en ejecución).
- `UpdateLayoutOrientation` traga excepciones con `catch (Exception ex) { }` (`:212`).
