# 02 — Lectura de QR (cuatro librerías × dos variantes)

> **Propósito:** explicar por qué hay 8 proyectos de lector QR, qué NuGet usa cada uno, cómo se traduce la API de una librería a otra, cómo se piden los permisos de cámara, el problema de ML Kit en el simulador iOS y qué dice la doc `qr-nuget`.
> **Fuente primaria:** `Ejemplos_Devices/QR/**` (8 proyectos + `Ejemplo_Docs_QR/`), `Ejemplos_Devices/Docs/qr-nuget/*.md`; de apoyo `Ejemplos_Devices/Docs/otros/propuesta-rosetta.md` y `.github/workflows/cd-ios-qr.*.yml` (sólo lo que toca al QR). Repo de código en el commit `285f6fb`.
> **Índices relacionados:** [00_MASTER-INDEX](00_MASTER-INDEX.md) · [01_Camara](01_Camara.md) · [03_Impresion-Termica](03_Impresion-Termica.md) · [08_App-Hibrida-Integrada](08_App-Hibrida-Integrada.md) · [09_CI-CD-y-Build](09_CI-CD-y-Build.md) · [10_Documentacion-Transversal](10_Documentacion-Transversal.md)

Todas las rutas son relativas a la raíz del repo de código `Ejemplos_Maui_Devices/`. Prefijo omitido en las tablas: `Ejemplos_Devices/QR/`.

**Por qué 8 proyectos.** Es una matriz didáctica **4 librerías × 2 patrones de UI**: el mismo lector se reescribe con cada NuGet para comparar APIs y su comportamiento en CI (sobre todo en el simulador iOS, §8). Los dos patrones son:

| Variante | Qué enseña | Páginas |
|---|---|---|
| **simple** (`X.LectorQR`) | Cámara embebida en la página principal; cada detección se muestra en un `DisplayAlertAsync` y se reanuda el escaneo. | `Pages/MainPage` |
| **_Dialog** (`X.LectorQR_Dialog`) | La página lectora se usa como «diálogo» que **devuelve un resultado**: `MainPage` hace `PushAsync` y espera un `TaskCompletionSource<List<QRContent>>`. | `Pages/MainPage` + `Pages/QRLectorPage` + `Models/QRContent` |

Historia: `BSM.*` nace de renombrar los antiguos `Ejemplo_LectorQR` / `Ejemplo_LectorQR_Dialog` (git registra `rename Ejemplos_Devices/QR/{Ejemplo_LectorQR_Dialog => BSM.LectorQR_Dialog}/…`). Los otros tres pares se agregaron después como alternativas (commits `camerascanner.maui ios`, `zn.lectorqr ios`, `bsn.lectorqr ios`…). La solución los agrupa por librería: `Ejemplos_Devices/Ejemplos_Devices.slnx:148-185`.

Los 8 proyectos son plantillas MAUI de proyecto único con el mismo esqueleto:

| Aspecto | Valor (todos) | Dónde |
|---|---|---|
| TFM | `net10.0-android`; `net10.0-ios` sólo si se compila en macOS | `*.csproj:4-5` |
| Mínimos | iOS 15.0 · Android 25 (API 25) | `*.csproj:24-25` |
| Android | `AndroidLdFlags=-Wl,-z,max-page-size=16384`, RIDs `android-arm;arm64;x86;x64` | simple `:28-31` · Dialog `:30-33` |
| `WindowsPackageType` | `None` (no se apunta a Windows) | `*.csproj:22` |
| Arranque | `App.CreateWindow` → `new Window(new AppShell())`; Shell con una sola `ShellContent` → `MainPage` | `App.xaml.cs`, `AppShell.xaml` |

## 5. Variante `_Dialog`: la página lectora como diálogo con resultado

### 5.1 Secuencia

```
MainPage                         QRLectorPage
───────                          ────────────
OnLeerQRClicked
 BtnLeerQR.IsEnabled = false
 PushAsync(new QRLectorPage) ──► ctor: formatos + BindingContext = this
                                 OnAppearing: pide permiso (resultado ignorado ⚠️)
                                              suscribe MainDisplayInfoChanged
                                              PaintFlashStatus + UpdateLayoutOrientation
 await ResultadoTask.Task ◄───┐
                              │  detección → Dispatch: pausar, CompletarResultado(QRs), PopAsync
                              └─ «Volver»  → CompletarResultado(lista vacía), PopAsync
 qrs.FirstOrDefault()
  ├─ != null → LbQR.Text = qr.Value
  └─ null    → DisplayAlertAsync("Cancelado", "No se recibió ningún dato")

```

`MainPage.xaml.cs:12-39` es **idéntico** en los 4 `_Dialog` (sólo cambia el namespace). Modelo: `Models/QRContent.cs:3-7` → `{ string Type; string Value; }`.

### 5.2 Piezas del patrón (referencias en `BSM.LectorQR_Dialog/Pages/QRLectorPage.xaml.cs`)

| Pieza | Líneas | Qué hace |
|---|---|---|

| `CompletarResultado` | `:136-142` | `Interlocked.Exchange(ref _completed, 1) == 0` → `TrySetResult`: completa **una sola vez** aunque lleguen varias detecciones o se toque «Volver» a la vez |

## 7. Permisos de cámara

### 7.1 Declaraciones de plataforma

| Elemento | simple (×4) | _Dialog (×4) |
|---|---|---|
| Android `CAMERA`, `VIBRATE`, `FLASHLIGHT` | ✅ | ✅ |
| Android `INTERNET`, `ACCESS_NETWORK_STATE`, `READ/WRITE_EXTERNAL_STORAGE` | ✅ | ✅ |
| `<queries>` `IMAGE_CAPTURE` | ✅ | ✅ |
| `FileProvider` en `<application>` | ✅ | ❌ |
| `uses-sdk` min 25 / target 36 | ✅ | ✅ |
| iOS `NSCameraUsageDescription` | «La app necesita acceso a la cámara para **tomar fotos**.» (`Info.plist:55-56`) | «…para **escanear códigos QR**.» (`Info.plist:59-60`) |

Los manifiestos y plist son una plantilla compartida con [01_Camara](01_Camara.md), de ahí los permisos de almacenamiento y el texto «tomar fotos» en las variantes simples.

Particularidades (descriptivas, no defectos):
- `CAMERA` se declara **dos veces** en `BSM.LectorQR/Platforms/Android/AndroidManifest.xml:20,23` y `BSM.LectorQR_Dialog/…/AndroidManifest.xml:14,17`.
- La authority del provider de `BSM.LectorQR` repite el sufijo: `…barcodescanner_mobile_maui.simple.simple.fileprovider` (`BSM.LectorQR/Platforms/Android/AndroidManifest.xml:11`).
- `ZN.LectorQR_Dialog/Platforms/Android/AndroidManifest.xml:2` no tiene atributo `package` (lo resuelve el `ApplicationId` del csproj).
- ⚠️ La ficha de `CameraMaui` dice que pide `RECORD_AUDIO`/`NSMicrophoneUsageDescription` y que se asigna `BarCodeDecoder = new ZXingBarcodeDecoder()` (`Docs/qr-nuget/02-alternativas-nuget.md:133,146`); los `ZN.*` no declaran micrófono ni asignan decodificador. No verificado si la 1.4.5 lo necesita.

### 7.2 Cuándo se pide el permiso en código

| Proyecto | Momento | ¿Bloquea si se deniega? |
|---|---|---|
| BSM / BSN / CS simple | al tocar linterna o cambiar cámara (`RequestCameraPermission`); BSM además en cada detección | sólo la linterna avisa «Dale permiso si queres QR!» |
| ZN simple | en `CamerasLoaded`, antes de `StartCameraAsync` (`ZN.LectorQR/Pages/MainPage.xaml.cs:24-28`) | **sí**: alerta y no arranca la cámara |
| 4 × `_Dialog` | `OnAppearing` → `await RequestCameraPermission();` (p. ej. `BSM.LectorQR_Dialog/…/QRLectorPage.xaml.cs:118`) | ⚠️ **no**: el `bool` se descarta; ZN es la excepción porque también lo chequea en `OnCamerasLoaded` (`ZN.LectorQR_Dialog/…/QRLectorPage.xaml.cs:54-60`) |

## 8. ML Kit y el simulador iOS

### 8.1 El problema

```
runner macos (Apple Silicon) ─► build simulador RID iossimulator-arm64
   BarcodeScanner.Mobile.Maui ─► Google ML Kit (MLKitCommon.framework)
   ML Kit trae slice arm64 de DEVICE y x86_64 de SIMULADOR, pero no arm64 de simulador
   ld: building for 'iOS-simulator', but linking in object file … built for 'iOS'
```

- Log real del fallo: `QR/Ejemplo_Docs_QR/cicd.md:121-132` (proyecto todavía llamado `Ejemplo_LectorQR_Dialog`); error clave en `:125`.
- Causa raíz explicada en `Docs/otros/propuesta-rosetta.md:12-37`: el IPA de dispositivo (`ios-arm64`) compila bien; falla sólo el build de simulador arm64.
- El build de **dispositivo** no se ve afectado («La app en iPhones reales funciona perfecto», `propuesta-rosetta.md:39`).

### 8.2 Las dos salidas presentes en el repo

| Salida | Cómo | Quién la usa |
|---|---|---|
| **Rosetta** — compilar el simulador como `iossimulator-x64` | Workflow: `RUNTIME_IDENTIFIER_SIMULATOR: iossimulator-x64` (`cd-ios-qr.BSM.LectorQR.yml:44-45`), runtime de simulador «universal» (`:149-155`), `softwareupdate --install-rosetta` (`:422-427`). Csproj: `AdamE.Google.iOS.GoogleUtilities` sólo con ese RID (`BSM.LectorQR_Dialog.csproj:78-80`). | `BSM.*` |
| **Cambiar de librería** — decodificar con Apple Vision/VisionKit (BSN, CS) o ZXing managed (ZN) | RID `iossimulator-arm64` en el workflow; sin dependencias de ML Kit en iOS (según la doc). | `BSN.*`, `CS.*`, `ZN.*` |

Detalle de los pasos del workflow → [09_CI-CD-y-Build](09_CI-CD-y-Build.md).

⚠️ `CS.LectorQR_Dialog` y `ZN.LectorQR_Dialog` conservan el `ItemGroup` de `AdamE` copiado de BSM (`:78-80`), aunque sus workflows compilan con `iossimulator-arm64`: con ese RID la condición no se cumple y el paquete no se agrega. BSN lo quitó, como indica `Docs/qr-nuget/05-plan-migracion.md:44-46`.

### 8.3 Lo que no resuelve ninguna librería

- El simulador iOS **no tiene cámara**: el escaneo real se prueba en un iPhone físico (`Docs/qr-nuget/03-matriz-rid.md:28`). El flujo Maestro lo aclara: «la vista se verá negra» (`Utilities/end2end/com.ejemplos.devices.qr.dialog.yaml:28-29`).
- Android x86: las librerías con ML Kit no lo soportan (`03-matriz-rid.md:27`); probar en un dispositivo arm64.

`Ejemplo_Docs_QR/Readme.md:66-115` junta otros intentos de compilación (`--ignore-native-library-conflict`, `--setenv:DYLD_LIBRARY_PATH=…`, `NoWarn MT5209;MT5212;MT5213`, build de dispositivo con `BuildIpa`), y `cicd.md:248-254` propone una «solucion» con `-gcc_flags "-Wl,-ignore_auto_link …"`. Ninguno de esos bloques figura en los csproj actuales (verificado: no aparecen `MT5209` ni `DYLD_LIBRARY_PATH` en `QR/*/*.csproj`).

## 13. Preguntas frecuentes y trampas

| Pregunta / trampa | Respuesta |
|---|---|
| ¿Cuál de los 8 conviene tomar como base? | Para iOS con simulador arm64, `BSN.LectorQR_Dialog`: es el que sigue el plan recomendado (`qr-nuget/04`, `05`) y es la librería que adoptó la app híbrida. |
| ¿Por qué el build de simulador de BSM falla con `ld: building for 'iOS-simulator'…`? | ML Kit no publica slice arm64 de simulador (§8.1). Usá `iossimulator-x64` + Rosetta (como los workflows BSM) o cambiá de librería. |
| ¿«ZN» es ZXing.Net.Maui? | ⚠️ No: es `CameraMaui` 1.4.5 (`Camera.MAUI` + ZXing). Sólo el nombre, el `ApplicationId` y la carpeta de la solución dicen ZXing.Net.Maui (§2). |
| ¿Por qué en BSN/CS la cámara no arranca? | Hace falta `CameraEnabled="True"`; BSM arrancaba solo (`05-plan-migracion.md:114`). En ZN hay que llamar `StartCameraAsync()` en `CamerasLoaded`. |
| ¿`QRCode` o `QR`? | BSN usa `QRCode` (`BarcodeSymbologies`), CS usa `QR` (`BarcodeFormats`), ZN `BarcodeFormat.QR_CODE`. No son intercambiables. |
| Si se deniega el permiso en un `_Dialog`, ¿qué pasa? | Salvo en ZN, la página se abre igual con la cámara sin imagen: `OnAppearing` ignora el resultado (§7.2). |
| ¿Puede `ResultadoTask` completarse dos veces? | No: `CompletarResultado` usa `Interlocked.Exchange` + `TrySetResult` (§5.2). |
| ¿Qué pasa si se vuelve con el gesto «atrás» del sistema en lugar del botón «Volver»? | No verificado en ejecución. Por código, `OnDisappearing` no completa la tarea (el `TrySetResult(null)` está comentado), así que `MainPage` seguiría esperando `ResultadoTask.Task`. |
| ¿Por qué hay un workflow `cd-ios-qr.Ejemplo_LectorQR_Dialog.yml`? | ⚠️ Quedó del proyecto renombrado: apunta a `Ejemplo_LectorQR_Dialog.csproj` (`:41`), que ya no existe en `QR/`. Ver [09](09_CI-CD-y-Build.md). |
| ¿El flujo Maestro `com.ejemplos.devices.qr.dialog.yaml` prueba un `X.LectorQR_Dialog`? | ⚠️ Por su contenido no: toca «Geo Posicionar», «Llamar» y «Leer QR» (`:20-30`), botones del pie de la app híbrida; los `MainPage` de `QR/` sólo tienen «Leer QR». Además, hoy ese botón híbrido dice «Geo Pos» (`Integrada/Ejemplo_Maui_Hibrida/Pages/MainPage.xaml:54`), no «Geo Posicionar». Ver [08](08_App-Hibrida-Integrada.md) y [09](09_CI-CD-y-Build.md). |
| ¿El `catch (Exception ex) { }` vacío de `UpdateLayoutOrientation` es un error? | Es una simplificación didáctica repetida en los 4 `_Dialog` (`BSM…QRLectorPage.xaml.cs:212`): un fallo de layout no tumba la página. |
| ¿Por qué BSN fija `Microsoft.Maui.Controls` 10.0.80? | El csproj no lo explica. La doc exige `>= 10.0.20` para BSN 3.0.4 (`05-plan-migracion.md:33`); el motivo exacto no está verificado. |
